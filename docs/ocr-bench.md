# 名刺 OCR の精度計測（ocr_bench）

本番 OCR（`OCR_PROVIDER=vertex`、`gemini-3.1-flash-lite`）の精度を、**文字起こし段階**と
**構造化段階**に分けて測るスクリプト。`backend/tools/ocr_bench/` に置き、プロダクトコードは
変更しない（`app.services.ocr` は読み取り専用で再利用）。

## 使い方

```bash
cd backend
uv run python -m tools.ocr_bench.measure \
  --images ../eval/cards \
  --truth ../eval/truth.json \
  --out ../eval/result.json \
  --provider vertex \
  --runs 2
```

| 引数 | 内容 |
| --- | --- |
| `--images` | 名刺画像のディレクトリ（jpg/png/webp） |
| `--truth` | 正解 JSON 1 ファイル、または 1 枚 1 JSON のディレクトリ |
| `--out` | 集計結果の JSON（値は含めない） |
| `--runs` | 同じ画像・同じ設定での繰り返し回数（既定 2） |
| `--limit` | 先頭 N 枚だけ測る |
| `--save-text` | 生の文字起こしを保存する（**本番データでは使わない**） |
| `--provider fake` | 外部通信なしの疎通確認・単体テスト用 |

正解 JSON は次の形。`transcript` は画像から書き写した全文、ほかのキーは項目の正解。

```json
{
  "card1": {
    "transcript": "株式会社サンプルテック\n営業部 課長\n山田 太郎\nTEL 03-1234-5678",
    "last_name": "山田",
    "first_name": "太郎",
    "company_name": "株式会社サンプルテック",
    "department": "営業部",
    "position": "課長",
    "contact_methods": [{"type": "tel", "value": "03-1234-5678"}]
  }
}
```

## 指標

| 段階 | 指標 | 定義 |
| --- | --- | --- |
| 文字起こし | CER | NFKC・空白除去後のレーベンシュタイン距離 ÷ 正解文字数 |
| 文字起こし | 文字一致率 | 1 − CER |
| 構造化 | 項目一致率 | 7 項目（姓・名・フリガナ2・会社・部署・役職）＋連絡先6種の完全一致率 |
| 構造化 | 捏造件数 | 画像の文字起こしにも正解にも含まれない値を出した件数（値は記録しない） |
| 性能 | 処理時間 | 文字起こし／構造化それぞれの中央値（ms） |
| 料金 | 概算 | 入力・出力トークン数。単価を渡したときだけ USD/JPY を算出 |

連絡先は種別ごとの集合で比較する（順序・重複は無視）。`others` は比較対象外。

## 実測（2026-11-28・ダミー6枚）

ダミー名刺 6 枚（印刷・異体字・縁なし撮影風・TEL/FAX 同居・氏名改行を含む）を、
本番と同じ Vertex 設定で 2 回計測した。値はすべてダミー。

| 回 | 項目一致率 | 文字一致率 | CER | 捏造 | 文字起こし中央値 | 構造化中央値 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0.987 | 0.997 | 0.0029 | 0 | 1009 ms | 1236 ms |
| 2 | 0.987 | 0.997 | 0.0029 | 0 | 909 ms | 1226 ms |
| ばらつき | min=max, σ=0 | σ=0 | σ=0 | 0 | — | — |

- 不一致は 1 項目だけ: 異体字「髙橋」の姓（文字起こしで「高橋」になった）。画像の文字を
  そのまま残す方針のため、正規化せず不一致として数えている。
- 2 回で全カード・全項目の一致結果が変わらなかった（`unstable_card_fields` はすべて 0）。
- トークンは 1 回あたり入力 17,284／出力 1,335（6 枚合計、1 枚あたり約 2,881／223）。
- 概算料金は `project.md` の本番実測「約 0.14 円/枚」を当てると 6 枚で 0.84 円。
  トークン単価を引数で渡せば USD/JPY の実額も出る。

再現コマンド（ダミー画像と正解はリポジトリに含めない）:

```bash
cd backend
uv run python -m tools.ocr_bench.measure --images <ダミー画像> --truth <正解JSON> \
  --out /tmp/result.json --provider vertex --runs 2
```

## 本番データの扱い

- 本番 DB の名刺 50 件・アップロード画像 178 枚は**件数の読み取りのみ**で、内容の取得・
  外部送信・ログ出力はしていない。
- 本番 49 件は正解ファイルが無く、Vertex へ再送すると「実在の名刺を外部サービスへ出す」
  ことになるため、この計測には使っていない。本番で測る場合は、人が正解を用意した
  ダミー相当のセットを別途作る。
- 出力 JSON と標準出力には値（氏名・会社名・番号）を含めない。`--save-text` は
  ダミーでのデバッグ専用。

## `ocr-bench/`（ブラウザ内試作品）の扱い

**取り込まない（捨てる）。** 理由: 比較対象が Tesseract / PaddleOCR のブラウザ WASM で
本番 Vertex の精度を測れず、モデル配布物（`public/ort`・`dist` 61MB・`node_modules` 242MB）
でリポジトリが肥大するため。ダミー名刺の作り方（条件を網羅する 6 枚）という発想だけを
本ドキュメントと単体テストのダミー画像に取り込んだ。
